# Родной список Workspaces - 0.3.0

Реализованы штатные Settings > Plugins > paseo-dialogs > Диалоги и сохраняемая
галка "Показывать родной список Workspaces", по умолчанию false. Значения
хранит registerSettings Paseo, обновление распространяется через useSettings.
Пока настройки не загрузились или недоступны, список не скрывается.

DOM-адаптер только в client/web.ts, Platform.OS web и некомпактный layout.
Он требует sidebar-project-list и sidebar-display-preferences-menu в общем
ограниченном контейнере без dialogs-block, других плагинов или sidebar-footer.
Сохраняет исходный inline display, восстанавливает его при включении настройки,
потере любой метки и cleanup плагина. MutationObserver обрабатывает замену
узлов и перезапись стилей. Не удаляет узлы и не меняет подвал.

## Проверено на отдельном демоне

Paseo 0.12.0, порт 6782, home в Library/Developer/paseo-dialogs/test-home.
Typecheck и 4 теста логики проходят. Дополнительный headless Chrome тест:
`node tests/browser/native-workspaces.mjs` (Playwright установлен вне Яндекс.Диска).
Проверяет скрытие обоих элементов, сохранение подвала, перерисовку, удаление
меток, восстановление inline display и отключение адаптера.
Галка проверена через штатные настройки и пережила plugin reload.

## Требуется уточнение метки

В реальном DOM тестового web-клиента нет sidebar-project-list, хотя бандл
Paseo передаёт этот testID в DraggableList. Есть только
sidebar-project-workspace-list-scroll и sidebar-display-preferences-menu.
По прямому требованию "если меток нет - ничего не скрывать" текущая реализация
оставляет список видимым. Снимки настроек и no-op сделаны на живом клиенте;
они не выдаются за доказательство успешного скрытия.

Чтобы скрыть реальное дерево этой версии, нужно разрешить фактическую пару
меток с проверкой безопасной границы контейнера. До этого доп. задача 0.3.0
заблокирована; основной Paseo не менялся.
