# Автоназвания 0.10.4

## Причина

В основном runtime 0.10.3 кандидат удалялся до генерации и записи имени.
Временная ошибка оставляла чат без дальнейших попыток:

- afcc5efe-01fc-450b-be94-1eb77186883d: 30.10.2026, 10:39:46.129Z, stage generation.
- 62c0d817-3eb1-46d0-bc63-897584c96695: 30.10.2026, 10:53:46.922Z, stage title_validation.

Следующие завершённые ходы записывали "нет кандидата". Исходный ответ модели не логировался,
поэтому конкретный текст отклонённого ответа восстановить нельзя.
Контрольный запрос к настоящему ai-fast с прежним max_tokens=40 использовал
41 completion token, из них 30 reasoning tokens. Это показывает, насколько мал запас
для самого названия; усечение конкретного исторического ответа не доказано.

## Исправление

Кандидат хранит completed, attempts и generated. После завершённого хода выполняется
не более трёх попыток с паузой в одну секунду. Попытка резервируется на диске перед
чтением истории и запросом. Готовое проверенное название сохраняется до записи имени,
поэтому повтор записи не требует нового обращения к модели. Кандидат удаляется после
успеха или подтверждённого ручного переименования, архивации либо смены типа чата.
Ошибка сохранения удаления возвращает кандидата в память. Исчерпанный кандидат
сохраняется для диагностики и не запускается на каждом новом ходе.

После reload первое dialogs.state от подключённого клиента возобновляет только
завершённые кандидаты с оставшимися попытками. Кандидаты ещё работающего первого хода
не запускаются. Защита naming предотвращает параллельные запросы. Cleanup прекращает
приём новых операций и ждёт уже запущенные переименования.

max_tokens увеличен до 256. Таймаут 20 секунд включает чтение JSON, а не только получение
заголовков HTTP. Требования к названию остались прежними: русские буквы, 24 символа,
один-два смысловых слова с допустимым служебным словом. Запрос прямо запрещает латиницу.
Перед генерацией и после неё заново проверяются имя, архив, головной статус и номер Канбана.

## Регрессии

npm run typecheck, npm test, git diff --check. 41 тест, 0 ошибок.
Модульные тесты вызывают настоящие обработчики runtime с контролируемыми внешними сбоями:

- Ошибка генерации, затем пустой ответ, затем успех за три попытки.
- Постоянная ошибка ограничена тремя попытками, включая новые ходы и dialogs.state.
- Сбой записи имени повторяется без нового запроса к модели.
- Ошибка записи state после получения названия сохраняет кандидата и готовое название.
- Ручное имя во время запроса и между повторными попытками не перезаписывается.
- Перезапуск регистрации плагина, чтение кандидата с диска и новое подключение клиента
  продолжают запись готового названия без повторного обращения к модели.
- Существующие проверки номеров Канбана, пагинации, пустой истории и параллельных хуков сохранены.
