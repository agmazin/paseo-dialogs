# Перенос диалогов - проверка AGM-31

Этот отчёт описывает первоначальную остановку. После разрешения оркестратора
на архивацию перед импортом блокировка снята. Итоговая проверка и реализация
0.5.0 описаны в `transfer-0.5.md`; исходные находки ниже сохранены как история.

Первый прогон 20.10.2026 завершился blocked. На момент остановки версия была 0.4.0.
Тогда обязательные ворота шага 1 не были пройдены; реализация ещё не начиналась.

## Проверка боем

Paseo и SDK 0.12.0, отдельный демон 127.0.0.1:6782,
home `/Users/agmazin/Library/Developer/paseo-dialogs/test-home`.
В одном каталоге `Library/Developer/paseo-dialogs/drag-fixtures` созданы
два локальных пространства:

- AGM31-source: `wks_472fcae789839f62`;
- AGM31-target: `wks_45623b5929938776`.

В первом создан Claude `2c4b8b77-f57b-4760-b236-249f8aa16e73`.
Пользовательский ход: "Запомни слово ЛИМОН. Ответь только: Запомнил.
Не используй инструменты." Ответ в `paseo agent logs`: "Запомнил."
Ход завершён, агент idle. Его сохранённая сессия:
`37f108fe-337e-4f7a-b938-4213e7b811bf`.

Внешним диагностическим клиентом выполнен запрос протокола, указанный в карточке:

```js
import { DaemonClient } from "@getpaseo/client/internal/daemon-client";

const client = new DaemonClient({
  url: "ws://127.0.0.1:6782/ws",
  clientId: "agm31-gate",
  clientType: "cli",
});
try {
  await client.connect();
  await client.importAgent({
    provider: "claude",
    sessionId: "37f108fe-337e-4f7a-b938-4213e7b811bf",
    cwd: "/Users/agmazin/Library/Developer/paseo-dialogs/drag-fixtures",
    workspaceId: "wks_45623b5929938776",
  });
} finally {
  await client.close();
}
```

Результат демона:

```text
Error: Provider session is already imported: 37f108fe-337e-4f7a-b938-4213e7b811bf
```

Таким образом, наличие `workspaceId` у import не означает возможность переноса
уже зарегистрированной сессии. Первый пункт ворот не выполнен: новый агент
во втором пространстве не создан. История в новом пространстве и продолжение
разговора не проверены. Codex не запускался: карточка прямо требует остановиться
при первом неуспешном условии. Скриншоты перетаскивания не создавались.
Старый агент до завершения проверки не архивировался и не удалялся.

## Граница API и варианты решения

В установленном `@getpaseo/client` 0.12.0 корневой экспорт не предоставляет
`DaemonClient`. Он доступен через `internal/daemon-client` и использован только
в отдельной проверке протокола, не в плагине.
Публичный `PaseoApi.agents` предоставляет list, ref, create, subscribe,
но не import. Клиент и сервер плагина получают этот же PaseoApi.
CLI `paseo agent import --help` также не содержит `--workspace`.
Публичная документация предписывает использовать соединение `usePaseo()`,
не создавать другое: https://paseo.sh/docs/plugins/reference.md#use-the-paseo-sdk.

1. Рекомендуется согласовать поддержку переноса в самом Paseo и публичном SDK,
   затем повторить ворота для Claude и Codex. Это должно сохранять историю и
   исключать два активных агента на одной сессии.
2. Отдельно можно согласовать исследование "сначала архивировать, затем импортировать"
   на тестовом демоне. Это другой порядок операций с необходимостью отката.
   Его работоспособность здесь не установлена; архивирование может не снять
   запрет повторного импорта.
3. Прямое редактирование файлов агентов, удаление старого агента ради импорта
   и отдельное внутреннее соединение из плагина не реализованы.
   Это обходы, требующие отдельного решения, а не готовый путь переноса.

## Завершение

Оба тестовых пространства и тестовый агент заархивированы через CLI.
После очистки `paseo workspace ls` и `paseo agent ls` на 6782 вернули `[]`.
Демон остановлен штатно по его home, `forced: false`, процесс завершился с кодом 0.
Chrome не запускался. Основной Paseo, его конфиг и плагин не изменялись.

Обновлены README.md, docs/spec.md и этот отчёт. Поиск `rg` по markdown
проектов agmazin и paseo-dialogs не нашёл других открытых пунктов AGM-31.
Код плагина и номера версий не менялись. Проверки перетаскивания 0.5.0
и тесты логики переноса не выполнялись, поскольку реализация остановлена на воротах.
