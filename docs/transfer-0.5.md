## Реализация и защита

На компьютере мышью перетаскивается строка активного или архивного диалога.
Параметры из 0.4.0: порог больше 6 px, вертикальное перемещение, масштаб 1.02,
прозрачность 0.9. Группа назначения подсвечивается; поднята и строка, и слой её
группы, чтобы соседняя группа не закрывала переносимый диалог.
Клик, Escape, потеря фокуса и отмена pointer работают отдельно от переноса.
На телефоне и в компактной раскладке жест не включается.

Сервер заново читает агента перед архивацией. Работающий, инициализирующийся,
имеющий активный ход или ожидающий разрешения агент получает подсказку
"Перенести можно, когда агент закончит". Проверяются исходное пространство,
сохранённая сессия Claude/Codex, отсутствие родителя, активное назначение и
совпадение каталога пространств. Два переноса одного ID не выполняются одновременно.

Название и метки восстанавливаются через updateAgent. Собственная зелёная
отметка и её маркер восстанавливаются; поздний markRead во время переноса
игнорируется. Кандидат автоназвания удаляется. Если диалог был открыт,
после переноса открывается его вкладка в новом пространстве.
Перенос из архива восстанавливает диалог активным в назначении, как штатный импорт.
Отдельно проверена уже открытая через родную "Историю" архивная вкладка:
она тоже следует в новое пространство. Порядок операций соответствует
согласованному "архивация, импорт"; повторная архивация назначения не выполняется.
При откате, напротив, восстанавливается исходный архивный статус.
Ограничение публичного API на первое закрепление архивной вкладки остаётся
тем же, что в 0.4.0.

При ошибке импорта или восстановления метаданных выполняется возврат в исходное
пространство. Если не удаётся и возврат, сообщение содержит provider, sessionId,
исходное пространство и просьбу обратиться к оркестратору.
До архивации сохраняется `plugin-data/paseo-dialogs/move-<agentId>.json`
с исходными метаданными, sessionId и unread. При успешном переносе или откате
он удаляется. Если процесс оборвался, файл остаётся, повторная попытка блокируется:
оркестратор должен проверить фактическое состояние и восстановить сессию,
затем убрать соответствующий журнал. Автоматического восстановления после
аварийного завершения процесса нет.

Внутренний модуль загружается динамически из зависимостей установленного
плагина, поэтому исчезновение экспорта не мешает остальной функциональности.
Проверяются методы, подключение к loopback-адресу из собственного paseo.pid,
совпадение serverId с файлом собственного home и точная проверенная версия демона 0.12.0.
Для иной версии перенос отключается до повторения ворот. Работает локальная
установка с ID `paseo-dialogs` и path в config.json; другие способы установки
этим адаптером не проверены и при отсутствии пути получают отказ без изменений.

## Что сохраняется и что не обещано

- Сохраняются ID агента, sessionId, текстовая история, название, метки,
  собственный unread. Успешный импорт делает диалог активным; откат сохраняет
  исходное архивное состояние.
- После загрузки сохранённой истории Paseo может заменить временный messageId
  последнего потокового ответа на ID из файла провайдера, а clientMessageId
  исходящего сообщения отсутствует в восстановленной записи. Это наблюдалось
  у Claude; содержание и порядок сообщений совпали. Тест исключает только эти
  временные идентификаторы при сравнении.
- Родные флаги внимания не копируются отдельной операцией. Пользовательская
  зелёная отметка принадлежит плагину и проверена отдельно.
- Собственный невидимый маркер прочтения повторно добавляется. Чужие элементы
  ленты плагинов не копируются и не гарантируются: они не являются частью сессии
  провайдера. Сохранность таких элементов в других плагинах не проверялась.
- Обновление времён и состояния процесса при archive/import выполняет Paseo.
  Новый агент и новая история не создаются, но отдельной старой архивной копии нет.

## Проверки

- `npm run typecheck`, `npm test`: 15 тестов. Среди новых: имя и метки,
  восстановление из архива, работа и разрешения, устаревшее пространство, отсутствующая
  сессия, ошибка импорта, ошибка метаданных, ошибка отката с sessionId,
  отсутствие внутреннего метода, отказ записи журнала и новый ход перед архивацией.
- `node tests/browser/dialog-transfer-live.mjs`: живой RPC и headless Chrome,
  отсутствие модуля без архивации, порог, Escape, слой поднятой строки, подсветка,
  перенос, история, ID, имя, метки, unread, клик, переход открытой вкладки,
  архив, компактная раскладка, перенос Codex. Ошибок pageerror нет.
- `node tests/browser/dialog-transfer-regression.mjs`: порядок групп 0.4.0,
  сохранение после page/plugin reload, сворачивание, меню "+", тёмная тема,
  отмена перетаскивания диалога. Ошибок pageerror нет.
- `node tests/browser/dialog-transfer-gate.mjs`: оба провайдера помнят слово
  после переноса; ошибочный workspaceId и реальный откат сохраняют историю.
- `node tests/browser/dialog-transfer-open-archive.mjs`: архивная вкладка,
  открытая через родную "Историю", следует за переносом и становится активной.

Успешные ответы "ЛИМОН" и JSON ворот получены до последующего ограничения
провайдера Claude на дополнительном повторном ходе. После этого новые ходы
Claude не запускались; финальные проверки интерфейса и перемещения использовали
уже сохранённую сессию. Сообщение провайдера тоже сохранилось в истории.
При проверке вкладок учитываются только видимые панели: Paseo сохраняет
скрытые панели прежнего пространства в DOM.

Снимки `01-before`, `02-during`, `03-after`, `04-escape`, `05-open-tab`,
`06-archive`, `07-compact`, `08-dark-during`, `09-memory-codex`,
`10-memory-claude`, `11-open-archive` лежат в игнорируемом artifacts/0.5.
Ключевые снимки и JSON ворот приложены к карточке.

Документы: README.md, OVERVIEW.md, docs/spec.md, docs/transfer-0.5-gate.md,
этот отчёт. Поиск rg по markdown обоих проектов выполнен: первоначальные
блокирующие формулировки обновлены, исторический отчёт сохранён с пояснением.

После проверки оба пространства и все тестовые агенты заархивированы.
Списки активных пространств и агентов на 6782 вернули `[]`.
Headless Chrome закрыт в finally, тестовый демон остановлен штатно по собственному
home, forced=false, процесс завершился с кодом 0. Основной демон, его конфиг,
плагин и окна не менялись. Зависимости остались вне Яндекс.Диска.
