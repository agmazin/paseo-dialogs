## Установка и обновление

Требуется демон Paseo 0.12.0 и `pluginsEnabled: true`.
`node_modules` - симлинк на `/Users/agmazin/Library/Developer/paseo-dialogs/node_modules`,
зависимости вне Яндекс.Диска. `npm ci` выполнять в отдельном каталоге зависимостей,
скопировав туда package.json и package-lock.json.

```sh
npm run typecheck
npm test
paseo plugin install /Users/agmazin/Yandex.Disk.localized/public/projects/local/paseo-dialogs --host 127.0.0.1:6782
paseo plugin reload paseo-dialogs --host 127.0.0.1:6782
paseo plugin ls --host 127.0.0.1:6782
paseo plugin logs paseo-dialogs --host 127.0.0.1:6782
```

6782 - только тестовый демон. Перезапуск для обновления плагина не нужен.

Основной Paseo Александра (с 20.10.2026) грузит плагин не из этого каталога, а из клона
по тегу принятой версии: `/Users/agmazin/Library/Developer/paseo-releases/paseo-dialogs`
(`node_modules` - тот же симлинк). Исполнители работают в этом каталоге на месте, и
перезагрузка из него подхватила бы черновик. Обновление после приёмки - у оркестратора:

```sh
git -C /Users/agmazin/Library/Developer/paseo-releases/paseo-dialogs fetch --tags origin
git -C /Users/agmazin/Library/Developer/paseo-releases/paseo-dialogs checkout vX.Y.Z
paseo plugin reload paseo-dialogs
```

## Откат

Тот же `checkout` на прежний тег и `paseo plugin reload paseo-dialogs`.
Быстро отключить: `paseo plugin disable paseo-dialogs`. Не делать reset общей рабочей копии.
Тег версии ставит оркестратор после приёмки.

## Данные и доступы

Состояние: `$PASEO_HOME/plugin-data/paseo-dialogs/state.json`, по умолчанию
`/Users/agmazin/.paseo/plugin-data/paseo-dialogs/state.json`. Хранятся порядок групп, свёрнутость, токены
непрочитанных ответов, кандидаты автоназвания и защита повторных действий.
Запись атомарная, каталог 0700, файл 0600. Маркер отдельный на каждый ход;
после потери маркеров демоном непрочитанные маркеры восстанавливаются при чтении
состояния. Старый маркер не снимает новый ответ.

Сервер читает только CLIPROXY_KEY_MAC и CLIPROXY_URL_MAC из
`projects/agmazin/.secrets/cliproxy.env`. Секрет не передаётся клиенту.
Название меняется один раз после первого успешного пользовательского хода;
ручное имя и архив не изменяются. Ошибка сети оставляет исходное имя.

## Ограничения Paseo 0.12

Родного черновика API нет: создаётся агент с настройками последнего агента
пространства и открывается родная вкладка. Браузер доступен только в Electron.
"Изменить профили" скрыто. Терминал создаётся SDK; выбор существующей вкладки
в web/Electron сделан через доступный элемент родного интерфейса, иначе открывается
пространство. Эти адаптеры изолированы в `client/web.ts`.

Перенос использует явно согласованный внутренний DaemonClient на сервере.
Он включён только для проверенного демона 0.12.0, локального TCP loopback,
установки с ID `paseo-dialogs` и путём в config.json, при наличии внутреннего модуля
и методов. Другая версия или недоступный модуль дают подсказку до изменения агента.
После обновления Paseo нужно повторить ворота и обновить проверку версии в адаптере.
На телефоне перенос недоступен; список отражает результат с компьютера.
Перенос из архива восстанавливает диалог активным в новом пространстве,
как штатный импорт Paseo. При неудаче откат возвращает его в исходный архив.

Paseo сохраняет ID существующего агента: отдельной копии в старом архиве нет.
При незавершённом переносе остаётся `move-<agentId>.json` в каталоге данных плагина
с sessionId и исходными метаданными. Повторная попытка блокируется до восстановления
оркестратором. Ни плагин, ни проверка не удаляют записи агентов или файлы провайдера.

`navigation.openAgent` открывает активные диалоги. Для архивных в Paseo 0.12
не передаётся `pin`, который использует родная "История": переход может оставить
предыдущую вкладку. Архив не разархивируется автоматически. Это известное
ограничение приёмки, открывать такие диалоги пока через родную "Историю".
